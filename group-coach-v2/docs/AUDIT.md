# 모듈 전수 검토 — 총 4회

2026-11-06 · 대상: **group-coach-v2 / wemeet_coach 0.1.1**. 기존 0.15.0 프로젝트는 수정·삭제하지 않았습니다. 아래 4회는 ‘조사 → 보완 → 재검사’ 단위입니다. 회차 안의 결함 재현과 수정 재검사는 별도 회차로 부풀리지 않았습니다.

## 무엇이 핵심인가

**AI 기능은 두 개입니다.** `group_coach`는 모임 코칭·공동 제안·반대 반영, `personal_coach`는 개인 질문·기여 계획입니다. 두 함수 모두 독립 호출할 수 있습니다. `validate_plan`은 AI를 부르지 않는 조건 검사입니다.

```python
from wemeet_coach import group_coach, personal_coach, validate_plan
from wemeet_coach import GroupRequest, PersonalRequest, Result
```

DB 저장을 함께 쓰려면 `from wemeet_coach.persistence import Store`를 별도로 가져옵니다. `web/`·`tools/web.py`는 이 모듈들을 시험하는 화면일 뿐, SW가 반드시 가져가야 하는 서비스가 아닙니다.

## 1회 — 참조·책임·불필요 코드

전체 패키지 17개 Python 파일과 테스트·예제·도구·마이그레이션의 참조를 조사했습니다.

- 실제 실행 경로가 없는 `m0/cache.py` 삭제. 동일 사용자 동작의 중복 유료 호출 방지는 계속 PostgreSQL operation 소유권이 담당합니다.
- `m0/records.py`의 단일 로그 래퍼를 삭제하고 필요한 JSONL 기록 기능만 `JsonlTraceSink`에 통합했습니다.
- 사용하지 않는 통신 통계 필드·개인 상태 변수·import 제거.
- 정리 후 기존 **35개 검사 통과**.

## 2회 — 코어 입력·근거·계획 검증

- 개인 코칭이 이미 처리한 옛 메시지를 새 변경 근거로 삼아 확인값을 바꾸는 경로를 차단했습니다. 새로운 실제 답변만 변경 근거로 사용합니다.
- 버튼으로 명시적으로 선택한 항목은 해당 응답에서 AI가 다시 해석해 덮어쓰지 못하게 했습니다.
- 마일스톤 기한 검사를 공통 `validate_plan`으로 통합했습니다. 직접 수정·외부 계획에도 같은 검사 경계가 적용됩니다.
- 0·음수·문자열·bool 시간 예산이 검사를 건너뛰는 문제와 개인 메시지 ID 중복을 차단했습니다.
- JSONL 비밀 제거 검사 등 추가 후 **43개 검사 통과**.

## 3회 — 저장·합의·장애

새 PostgreSQL에서 아래 3건의 수정 전 실패를 실제 재현하고 기록했습니다.

| 결함 | 보완 |
|---|---|
| AI 실패 시 버튼 선택 메시지는 남지만 확인 조건이 남지 않음 | 본인 선택을 모델 호출 전에 state로 커밋 |
| Python 직접 호출은 문자열 투표를 허용 | `agree`는 bool만 허용, HTTP와 같은 경계 |
| 수준이 미확인으로 바뀌어도 수동 수정으로 계획 생성 가능 | 수동 계획도 수준·시간·기여 범위 확인 요구 |

반대·새 투표·1/3/5/8명 만장일치·동시 실행·암호화 저장 복구·공개/개인 분리의 기존 검사를 유지하며 **46개 검사 통과**.

## 4회 — SW 독립 연결·최종 설치·정리

- 공개 import를 패키지 루트에 모아 내부 경로를 알아야 하는 부담을 줄였습니다.
- 저장된 기록 조회에 `--live`를 요구하던 예제 조건을 고쳤습니다. 조회는 AI 호출이 없습니다.
- 한 사람의 비공개 조건 변경이 진행 중인 공동 코칭까지 STALE로 만드는 의존성 문제를 수정했습니다. 공동 실행은 공개 이벤트·구성원 변경, 개인 실행은 본인 조건·승인 공동 버전을 비교합니다. 기존 실행 스냅샷의 호환 경로도 유지했습니다.
- 전체 **47개 검사 통과**. TestClient 의존성의 사용 중단 예정 경고 1건은 남아 있습니다.
- 익명 시나리오 **200개 입력 계약 검사: 200개 통과**. 이는 200개 LIVE 품질 검사가 아닙니다.
- 실제 Timely 공동 코칭·버튼 개인 코칭 **각 1건 성공 / 총 HTTP 2회 / 4,080 tokens**. 실제 답변 저장과 다음 질문 연결을 확인했습니다. 이후 최종 공개/개인 의존성 보완은 코드 재검사로 확인했습니다.
- 새 환경에 0.1.1 wheel만 설치해 공개 함수와 최소 예제를 실행했습니다. 기존 `wemeet_ai`·FastAPI·SQLAlchemy·psycopg 없이 코어를 사용할 수 있습니다.

## 삭제·정돈 결과

- 제품 Python 파일: **17 → 15개**, 줄 수 **1,130 → 1,103줄**. 필요한 결함 수정은 남기고 수치만 줄이려고 기능을 없애지 않았습니다.
- 사용되지 않는 캐시/로그 래퍼 2개 삭제. 실패 재현 테스트는 삭제하지 않았습니다.
- 이전 wheel·중간 build·시험 임시 폴더·설치 확인용 가상환경·생성 캐시 삭제. 현재 서버의 `.venv`, DB·대화·암호화 복구 기록은 보존합니다.
- 여기저기 있던 검증 JSON/화면은 `docs/evidence/`, JSON Schema/OpenAPI는 `docs/contracts/`로 이동했습니다.
- 네 회차의 테스트 출력·소스 해시·수정 전 실패·LIVE 정보·설치 검증은 **[audit/results.json](audit/results.json)** 한 파일로 합쳤습니다. 중복 중간 보고 파일은 삭제했습니다.
- 최신 wheel과 최종 소스 일치, 기존 소스 60개 불변, 기존 DB 최초 비교 기준과 동일, 소스·문서의 실제 키/접속 주소 유출 없음.

## 판정과 한계

**모듈 연결·개발 시험에 사용 가능**합니다. SW팀은 루트 README의 세 함수와 선택 Store부터 보면 됩니다. [연결 계약](INTEGRATION.md), [DB 운영](DATABASE.md)은 필요한 경우에만 읽으세요.

이번 검토를 운영 서비스 인증·권한 완성이나 사람의 인수 승인으로 보지 않습니다. AI 조언의 전반적 의미 품질을 두 LIVE 호출만으로 보장하지도 않습니다. 운영 백업 복원 리허설·다중 서버 장애·전 화면 너비의 시각 검사는 별도 범위입니다. 모델이 작성한 추천·공개 요약은 사용자의 검토가 필요합니다.
