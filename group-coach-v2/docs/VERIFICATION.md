# 0.1.2 — 개인 계획 근거 오류·공동 코칭 가독성 수정

- 저장된 실패 입력의 개인 조건 8개는 모두 올바른 근거를 참조했습니다. PLAN이 state를 모델로 다시 생성하지 않고, 코드가 확인 조건을 유지하도록 분리했습니다.
- 새로운 사실에 가짜 근거를 붙이는 출력은 계속 거부합니다. 필수 조건 누락은 유료 호출 전에 NEEDS_INPUT으로 반환합니다.
- 공동 COACH는 **정해진 내용 / 결정할 내용 / 더 구체화하면 좋은 내용 / 다음 행동**으로 짧게 답합니다. 실제 투표 상태를 전달해 채팅의 찬성 의견과 공식 승인을 구별합니다.
- 채팅은 제목·불릿·굵은 글씨를 HTML 실행 없이 표시합니다. 과거의 긴 답변은 접어서 볼 수 있습니다.
- 사용자 승인 후 보고된 실패 계획을 새 비공개 버전으로 복구했습니다. 처음 생성한 계획에서 주말 밖 작업을 발견해 요일 검증을 추가하고 다시 생성했습니다. 최신 초안은 주말 작업 4개·총360분·개인 조건8개 유지, 기간·시간 예산·요일 검사 통과입니다. 모임 공유나 본인 확정은 실행하지 않았습니다.
- 실제 검증은 총 HTTP4회(개인2회, 익명 공동2회, 각각1HTTP)입니다. 최종 개인 생성20,095ms, 공동 코칭 약6초를 관측했습니다. 지연 개선율을 보장하는 비교 실험은 아닙니다. 개인 조건의 외부 재전송은 구체적인 사용자 승인 후 실행했습니다.
- 최신 회귀: **53 passed**. [실행 기록](evidence/clarity-check.json) · [공동 코칭 화면](evidence/coaching-clarity.png).

## 발견 문제와 처리

1. 자연어 코칭 응답 잘림: 출력 한도를 늘리고 잘림을 실패로 구분했습니다.
2. 역할 객체가 닉네임을 키로 사용: 실제 member_id 목록을 포함한 보정 안내를 추가했습니다.
3. 기간 밖 작업: 코드 검증으로 거부하고 기간 범위를 명시해 재요청했습니다.
4. 개인 도구/제약이 문자열로 반환: 의미를 보존해 한 항목 목록으로 정규화합니다. 모름·건너뛰기는 null로 별도 보존합니다.
5. 명시한 개인 범위를 UNKNOWN으로 남긴 사례: 무한 재질문하지 않고 본인 조건 수정으로 확인한 뒤 실패한 개인 단계만 재실행했습니다. 이 사례는 완전 자동 추출 성공으로 집계하지 않습니다.
6. 사진 인증을 사진 공개로 확대했던 브라우저 초안: 반대로 보류한 뒤 수정안에서 ‘완료 여부만 공개’로 고치고 새 만장일치를 확인했습니다. 원본 인증과 공개 범위를 분리하는 프롬프트를 보완했습니다.

따라서 API 성공을 의미적 완벽함으로 판정하지 않습니다. 특히 자연어 공개 범위·범위 추출은 사용자의 카드 검토와 확인이 필요합니다. 합성 개인 표식의 공개 혼입은 네 사례에서 발견되지 않았으나 모든 의미적 재식별을 증명한 것은 아닙니다.

## 인수 판단과 남은 범위

**로컬 통합 시험과 SW 연결 검토에 사용 가능**합니다. 첫 목표인 ‘공동 대화→제안→반대 반영→만장일치’를 확인했고 개인 상담·공개 공유까지 연결했습니다.

아직 운영 서비스 인수 완료는 아닙니다. 실제 인증·소속 권한·사용자 동의는 SW가 구현해야 합니다. 실사용자 내용 평가, 운영 백업 복원 리허설, 여러 서버 프로세스 장애/네트워크 전체 시험, 모든 반응형 너비의 정식 시각 검사는 별도로 남아 있습니다. 동일 프로세스 동시 실행 검사를 다중 서버 운영 검증으로 확대 해석하지 않습니다.
