# 1단계 — 인증

## 목표

회원가입, 아이디 중복 확인, 로그인·로그아웃, 서버 측 세션과 승인된 비밀번호 복구 정책을 실제 DB 상태로 제공한다.

## 선행 게이트

0B-1과 0B-3이 통과하고, 0B-2가 `DETERMINISTIC PASS`이며 계정/비밀번호 복구 기본 정책이 활성 문서에 기록돼 있어야 한다. 0B-2 LIVE 확인은 BLOCKED 상태여도 인증을 진행할 수 있다.

## 수행

1. 원본 signup/login 화면을 별도 templates/static 경로로 복제해 실제 폼과 오류·로딩 상태에 연결하라. 원본 landing 화면도 같은 방식으로 복제하되 서버 데이터는 연결하지 않는다. 상단 로그인·회원가입 링크는 해당 화면으로, 맨 아래 `그룹 생성 · 참여하기` CTA는 D-A5에 따라 로그아웃 상태면 로그인 화면(성공 뒤 dashboard), 로그인 상태면 dashboard로 연결하라. 원본처럼 `moim-invite`로 직접 보내지 마라.
2. Argon2id 해시, 세션 회전·만료·로그아웃 폐기, 환경별 안전한 쿠키를 구현하라.
3. 중복 확인과 로그인에 rate limit, 계정 열거 완화, 일반화된 오류 응답을 적용하라.
4. CSRF, 입력 정규화/길이 제한, 자동 이스케이프를 적용하라.
5. 이메일/SMS 외부 계정이 승인되지 않았다면 비밀번호 복구를 제공하는 것처럼 꾸미지 말고 비활성 상태와 지원 범위를 명확히 표시하라.

범위 밖: OAuth, 그룹/초대, 프로필 편집, 클라이언트 토큰 저장, 원본 HTML 변경.

## 검증

- 정상·중복·잘못된 입력·잠금/제한·로그아웃·만료·새로고침을 브라우저와 API에서 검증하라.
- 비밀번호 평문/세션 ID가 DB·로그·HTML/localStorage에 없는지 확인하라.
- CSRF, 세션 고정, 계정 열거, XSS를 결정적 테스트로 검증하라.
- 원본 HTML 해시를 검사하고 1440×900 스크린샷 캡처를 실행해 사용자가 원본과 나란히 확인할 수 있게 하라.

## 중단 조건

외부 이메일/SMS 계정 또는 개인정보 정책 변경이 필요하면 승인 전 중단하고 BLOCKED로 보고한다. 범위 밖 기능은 시작하지 않는다.
