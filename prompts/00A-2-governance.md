# 0A-2 — 운영 문서와 헌법 이관

## 목표

승인된 GATE A 결과를 장기 활성 규칙과 가변 운영 문서로 정확히 이관하고, 규칙의 단일 원본과 추적성을 확립하라.

## 선행 게이트

현재 HTML 9개의 LOCKED 디자인 기준 승인과 Timely LIVE 허용 여부/0B 예산 결정이 기록돼 있어야 한다.

## 수행

1. `AGENTS.md` 상단 헌법 영역에 bootstrap의 제품 목표, 변경 불가 원칙, 결정·승인 정책, 작업 중단 조건, 저장소 우선순위와 개정 절차를 원문 의미를 축약하지 않고 이관하라.
2. `docs/PRODUCT.md`, `ARCHITECTURE.md`, `SECURITY.md`, `LIVE_TESTING.md`, `ROADMAP.md`, `HANDOFF.md`를 책임별로 생성하라. `CLAUDE.md`는 `@AGENTS.md` 한 줄로 둔다.
3. 0A-1의 모듈별 KEEP/ADAPT/REPLACE/DROP 판정표와 다섯 평가 기준에 대한 근거를 `docs/ARCHITECTURE.md`에 기록하라. 이후 단계는 이 문서를 판정의 단일 원본으로 사용한다.
4. 디자인 해시 기준표, 승인 문장·날짜·결정 ID(`prompts/README.md`의 D-A5 포함), OPEN 항목, §1~§12 규칙 추적표를 기록하라.
5. 헌법과 운영 문서에 서로 다른 상태의 중복 규칙이 없게 하라.
6. `AGENTS.md` 일반 실행 규칙에 다음 뜻을 명시하라: "단계 작업 시 `prompts/README.md`의 공통 실행 계약과 `prompts/VALIDATION.md`를 적용하고, 작업 종료 시 `docs/HANDOFF.md`를 현재 상태로 갱신한다." `AGENTS.md`는 매 작업마다 읽히므로 헌법 영역을 포함해 가능하면 200줄 이하로 유지하라. 줄 수를 맞추려고 헌법 문장을 축약하지 말고, 일반 실행 설명은 해당 `docs/` 문서로 옮긴 뒤 `AGENTS.md`에는 그 문서 경로만 남겨라. `prompts/README.md`의 컨텍스트 절약 규칙 중 큰 파일 검색 읽기 규칙을 일반 실행 규칙에 반영하라.

범위 밖: 앱 코드, DB, 의존성, 원본 HTML 변경, 0B 이후 구현.

## 검증

- 원문 절과 이관 문장을 항목별로 대조하고 누락·의미 약화가 0개인지 확인하라.
- `docs/ARCHITECTURE.md`에 M0, M1 A~F, M2, persistence가 각각 판정 하나와 근거를 갖는지 확인하라.
- 모든 추적표 링크와 파일 경로가 실제로 존재하는지 검사하라.
- 원본 HTML 해시가 승인 기준과 동일한지 확인하라.
- 문서 전용 결정적 테스트 또는 검사 스크립트가 있다면 실행하라.

## 중단 조건

승인 기록이 불명확하거나 승인값과 기준표가 충돌하면 추정하지 말고 중단한다. 헌법 문구 변경은 별도 사용자 승인 없이는 하지 않는다.
