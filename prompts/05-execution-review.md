# 5단계 — 실행과 투두별 M2 평가

## 목표

실제 진행률·일정·투두·활동을 기록하고, 사용자가 특정 투두에 자료를 첨부하면 M2가 그 투두에 숨겨 저장된 결과물·완료 기준에 따라 자료를 기준별로 검토·평가하게 한다. M2 결과 표시와 투두 완료 반영은 GATE D에서 승인된 기존 화면 재사용 방식으로 구현한다.

## 선행 게이트

GATE D의 허용 파일 형식, 첨부 보관·삭제 정책이 승인돼 있어야 한다. M2.review는 vision 지원이 확인되고 사용 범위·이의 제기 정책과 5단계 Timely LIVE 예산이 승인된 경우에만 활성화한다. M2가 `LIVE BLOCKED/비활성`이어도 일반 실행·제출·수동 완료 확인은 진행한다.

## 수행

1. 원본 group 화면의 진행률·투두·활동 영역을 templates/static으로 구현하고 4단계에서 확정된 역할·투두 API와 연결하라. private 정보는 표시하지 마라.
2. 활동·진행률·투두 상태 변경을 사용자/시간/revision과 함께 감사 가능하게 저장하라.
3. 첨부는 반드시 제출자 본인의 특정 `task_id`와 그 투두의 확정 revision에 연결하라. 첨부파일은 승인된 형식·크기·개수로 제한하고 콘텐츠 유형 검증, 안전한 저장 이름, 접근 인가를 적용하라.
4. M2가 활성화된 경우 검토 입력을 해당 투두의 불변 snapshot으로 제한하라: 투두 제목, 내부 `deliverable`, `completion_criteria`, 허용 증거, 제출 설명과 그 투두에 첨부된 자료. MemberState·전체 private 대화·profile, 다른 구성원이나 다른 투두의 데이터는 보내지 마라.
5. M2는 각 `completion_criteria`를 근거와 함께 평가하고 전체 결정을 `PASS`, `REVIEW_NEEDED`, `NEEDS_INPUT` 중 하나로 저장하라. M2가 기준을 바꾸거나 프로젝트 전체 완료를 선언하지 못하게 하라. PASS의 투두 완료 반영과 체크박스 동작은 GATE D에서 승인된 규칙을 적용하라.
6. GATE D 승인대로 기존 `up-msg`와 팀원 완료 기록을 우선 재사용해 평가 상태·보완 안내·이의 제기를 표시하라. 평가 기준 원문을 별도 검토 UI로 노출하거나 승인되지 않은 새 패널을 추가하지 마라. M2 비활성 시에는 기존 수동 완료 흐름을 유지하라.
7. provider와 앱 로그에 파일 내용/data URL/private 원문을 남기지 마라.
8. 기존 `M2.review`와 completion persistence 후보를 우선 검토해 특정 task snapshot·첨부·기준별 평가·멱등 submission/review 계약을 재사용하되 MOIM 개인정보 경계를 우회하지 마라.

범위 밖: 별도 개인 목표 엔터티·화면, 평가 기준 검토 UI, 승인되지 않은 M2 결과 패널·체크박스 의미 변경, 승인되지 않은 OCR/vision, 평가 기준의 M2 임의 변경, 다른 투두·구성원의 자료 평가, 프로젝트 전체 자동 완료, 계정 삭제, 원본 HTML 변경.

## 검증

- 그룹 화면에 확정된 역할·투두만 표시되고 draft·private 원문·조건이 템플릿·응답·화면에 없는지 확인하라.
- 교차 사용자/그룹 파일 접근, 확장자 위장, 경로 조작, XSS 파일명, 크기 초과를 결정적 테스트로 차단하라.
- 첨부와 M2 요청이 정확히 하나의 제출자·task_id·투두 revision·숨겨진 평가 기준 snapshot에 묶이는지 검증하라.
- 기준별 PASS/미통과/정보 부족, GATE D에서 승인된 완료 반영·체크박스 동작·결과 표시, 보완 제출, 이의 제기, 재검토, 중복 제출, revision 충돌과 새로고침 복구를 검증하라.
- MemberState·다른 투두·대화가 M2 입력·출력·로그에 섞이지 않는지 의도적으로 심은 private fixture로 검증하라.
- M2가 활성화된 경우에만 Timely LIVE를 이 단계의 최대 3회 예산 안에서 수행해 호출 수·latency·usage·오류를 기록하라. GATE D의 vision·파일 처리 확인 결과는 재사용하고 반복하지 마라. M2 비활성 상태에서는 일반 실행·제출·수동 완료 경로를 검증하라.
- 원본 HTML 해시를 검사하고 1440×900 스크린샷 캡처를 실행해 사용자가 원본과 나란히 확인할 수 있게 하라.

## 중단 조건

파일 보관/삭제 정책, 악성 파일 대책 또는 개인정보 범위가 불명확하면 중단하고 BLOCKED로 보고한다. LIVE 승인 부재는 M2만 비활성화하며 일반 실행·제출을 막지 않는다. 범위 밖 기능은 시작하지 않는다.

## 완료 보고

투두와 숨겨진 기준→첨부→M2 기준별 평가→승인된 기존 화면의 완료/보완/이의 흐름, 파일·개인정보 보안, 결정적/LIVE/디자인 검증, 다음 한 단계(6단계)를 보고하라.
