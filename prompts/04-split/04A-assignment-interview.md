# 04 세션 A — 역할 배정, coverage, 배정 후 인터뷰 (수행 1~6)

주 실행 프롬프트는 `prompts/04-role-todos.md`다. 이 파일은 그 프롬프트의 수행·검증 절을 세션별로 나눈 것이며 내용을 바꾸거나 완화하지 않는다. 충돌하면 `prompts/04-role-todos.md`, `AGENTS.md`가 우선한다. 4단계는 세션 C가 끝나기 전까지 완료가 아니다. 5단계는 시작하지 않는다.

## 공통 규칙 (세션 A·B·C 동일)

- 새 세션에서 시작한다. 이전 맥락은 대화가 아니라 `docs/HANDOFF.md`와 활성 문서에서 이어받는다. 작업 전 `AGENTS.md`, `prompts/README.md`, `prompts/VALIDATION.md`, `docs/HANDOFF.md`, `docs/PRODUCT.md`(D-B1·D-B3·D-B4), 실제 코드를 읽는다. 문서와 코드가 다르면 실제 코드를 근거로 보고한다.
- 선행 게이트를 확인한다: 3단계 완료 기록, D-B4 승인 기록. 없으면 BLOCKED로 그 사실만 보고한다.
- 03 프롬프트와 이전 보정 프롬프트는 쓰지 않는다. 3단계를 다시 구현하거나 배정 전 인터뷰를 복원하지 않는다.
- 원본 HTML 9개, `prompts/04-role-todos.md`, `AGENTS.md` 헌법 영역, PRODUCT.md의 기존 승인 결정을 수정하지 않는다.
- 반복 실행에는 변경과 관련된 테스트만 돌린다. 전체 결정적 테스트와 교차 단계 회귀는 세션 C가 단계 종료 때 한 번 실행한다.
- LIVE 호출은 D-A8을 따른다. 모든 호출의 call_id·request_id·latency·usage와 누적 호출 수를 `docs/LIVE_TESTING.md`에 기록하고 fixture를 LIVE로 보고하지 않는다. 누적이 단일 작업 100회에 가까워지면 멈추고 사전 승인을 받는다.
- 세션 종료 시 `docs/HANDOFF.md`를 현재 상태로 갱신한다. `4단계 진행` 절에 이번 세션의 완료 범위, 만든 파일·테이블·API, 다음 세션이 알아야 할 사실, 남은 OPEN을 적는다. ROADMAP.md에서 4단계를 완료로 바꾸지 않는다.
- 커밋하지 않는다. 사용자가 확인한 뒤 커밋한다.
- 마지막 보고는 `결과 / 검증 / 달랐던 사실 / OPEN·BLOCKED / 다음 한 단계` 순서이며 빈 항목은 채우지 않는다.
- 중단 조건(04 프롬프트 `중단 조건`)에 해당하면 추측으로 진행하지 않고 BLOCKED로 보고한다. 같은 원인의 실패가 3회 반복되면 같은 시도를 멈추고 시도·공통 원인·대안·필요한 조치를 보고한다.
- 수행 12(서버에서만 AI 호출, 브라우저는 Timely·키를 다루지 않음, 출력은 `textContent`/템플릿 이스케이프만, 오른쪽 팀 목표 박스는 2단계 표시문을 읽기 전용으로 표시)는 모든 세션의 공통 제약이다.
- 3단계의 "배정·투두 금지" 경계 테스트가 이번 세션의 변경으로 실패하면, 그 테스트만 4단계 계약에 맞게 고치고 무엇을 왜 고쳤는지 HANDOFF에 남긴다(수행 13의 일부를 앞당기는 것이며 검증을 약화하지 않는다).

## 이 세션의 범위

`prompts/04-role-todos.md` 수행 **1~6**만 한다.

1. 3단계 출력 계약 확인(코드 읽기).
2. 서버 역할 배정 서비스: 1→2→3순위, 충돌·소진 때만 서버 무작위, immutable assignment revision, 한 번만 저장, 주입 가능한 RNG.
3. `ROLE_TODOS`와 배정 후 인터뷰 하위 상태를 안전한 마이그레이션으로 추가(upgrade → downgrade → upgrade, 기존 인터뷰 데이터 보존).
4. 팀 coverage: AI 한 번 생성, 서버 ID 수준 검증, 실패는 오류·명시적 재시도, 대체 목록 없음.
5. 서버에 고정된 배정 결과를 기존 AI 말풍선 스타일로 안내(Timely 호출 없음). 오른쪽 `내 역할`에 역할명과 `N순위로 배정`.
6. AI 주도 인터뷰: 새 session·MemberState·입력 snapshot을 `source_assignment_revision`에 연결, 필수 2개·최대 5개 질문·UNKNOWN 허용·의미 없는 입력 비소비·확인·수정은 기존 말풍선/입력창 안에서만. 한 사용자의 미완료가 다른 사용자를 막지 않는다.

하지 않는 것: 투두 초안·수정·확정(수행 7~10), 재배정(11), 최종 문서 정리(13).

## 이 세션에서 지킬 설계 조건

- 세션 B가 `source_assignment_revision`과 coverage, 인터뷰 snapshot을 입력으로 읽는다. 이 연결 키를 HANDOFF에 정확히 적어라.
- 세션 C의 재배정·STALE이 인터뷰 snapshot과 coverage를 무효화할 수 있도록, 이 데이터에 assignment revision과 STALE 표시를 둘 수 있는 구조로 저장하라.

## 이 세션의 검증 (04 프롬프트 `검증` 절 중)

배정, coverage, 인터뷰, 보안·개인정보(배정·인터뷰 범위), 공급자 입력(coverage·인터뷰 호출에 B3 금지 항목 없음), 복구(ROLE_TODOS·인터뷰 진행 새로고침·서버 재시작), 마이그레이션 up/down/up, Timely LIVE(coverage·인터뷰 턴. 서로 다른 역할 3종 이상으로 질문이 역할마다 달라지는지 사람이 판정할 수 있게 기록).

## 완료 조건

위 범위가 결정적 테스트와 LIVE로 확인되고 HANDOFF에 `세션 A 완료`가 기록돼 있다. 다음 한 단계는 세션 B다.
