# 6단계 — 마이페이지와 계정 생명주기

## 목표

사용자 정보·설정·비밀번호 변경과 승인된 그룹 탈퇴/계정 탈퇴 정책을 원본 디자인 안에서 안전하게 구현한다.

## 선행 게이트

GATE D의 그룹 탈퇴, 계정 삭제·익명화·보관, 첨부 삭제 정책이 명시적으로 승인·기록돼 있어야 한다.

## 수행

1. 원본 mypage 화면을 templates/static으로 구현하고 실제 사용자 데이터에 연결하라.
2. 비밀번호 변경은 현재 비밀번호 확인, Argon2id 재해시 필요성, 세션 회전/다른 세션 폐기 정책을 적용하라.
3. 그룹 탈퇴, 그룹장 위임/중단, 계정 탈퇴의 영향 미리보기와 재확인을 구현하라.
4. 승인 정책대로 삭제·익명화·보관 작업을 트랜잭션과 감사 기록으로 수행하라.
5. 되돌릴 수 없는 작업은 명확히 구분하고 실패를 부분 성공으로 표시하지 마라.

범위 밖: 승인되지 않은 데이터 삭제, 새 프로필 공개 필드, 소셜 로그인, 원본 HTML 변경.

## 검증

- 재인증, CSRF, IDOR, 세션 폐기, 마지막 그룹장, 보관 FK, 부분 실패를 결정적 테스트로 검증하라.
- 삭제/익명화 후 API·템플릿·검색·첨부·로그에 남는 데이터가 승인 정책과 일치하는지 확인하라.
- 원본 HTML 해시를 검사하고 1440×900 스크린샷 캡처를 실행해 사용자가 원본과 나란히 확인할 수 있게 하라.
- 범위 밖 데이터가 삭제되지 않았는지 백업 fixture로 확인하라.

## 중단 조건

승인된 생명주기 정책이 없거나 실제 사용자 데이터에 되돌리기 어려운 작업이 필요하면 중단하고 BLOCKED로 보고한다.
