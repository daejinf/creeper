# 8C단계 — 포트폴리오 RAG: 검색·근거 게이트·인용 답변

## 목표

사용자 질문에 대해 본인 첨부 파일 노드만 검색하고, 근거가 있을 때만 인용이 달린 답을 만든다. 근거가 없으면 생성 호출 없이 거절한다. 답의 모든 문장은 첨부 파일 안의 위치(파일·쪽·슬라이드·시트)로 돌아가야 한다. 기술 기준은 `docs/RAG_DESIGN.md` 3절(3.1~3.8)이다.

## 선행 게이트

- `08B-rag-understanding.md`가 완료되어 `docs/HANDOFF.md`에 기록돼 있어야 한다. 아니면 BLOCKED로 보고한다.
- D-I1이 승인 상태여야 한다. LIVE는 D-A8을 따른다.

## 수행

1. 범위 고정을 구현하라(설계 3.1). 모든 검색은 서버 세션 사용자로 `user_id`와 `READY`를 먼저 고정한다. 프로젝트·기간 필터는 그 안에서만 좁힌다.
2. 작은 코퍼스 우회를 구현하라(설계 3.2).
   - 판단 기준은 **최종 생성 입력 전체의 예상 크기**다. 시스템·스키마 지시, 모든 노드의 색인 텍스트(머리말·맥락·원문), 요약 노드, 구분자, 앞뒤 질문을 모두 더한다.
   - 이 합이 6k 토큰 환산 이하면 검색·재정렬·질문 임베딩 없이 전부 넣는다.
   - 표본 호출의 `usage.prompt_tokens`와 예상값의 오차를 기록하라.
3. 1단계 후보를 구현하라(설계 3.3).
   - 질문 임베딩 1회, `numpy` 내적으로 top-50.
   - 앱 측 BM25(`k1=1.2, b=0.75`, 사용자 범위 IDF)로 top-50.
4. RRF(`k=60`)로 합치고 노드 id로 중복을 없앤 뒤 상위 25개를 남겨라(설계 3.4). 사용자당 노드 수별 적재·계산 시간을 측정해 `docs/HANDOFF.md`에 기록하라.
5. 재정렬과 근거 게이트를 구현하라(설계 3.5).
   - LLM 1회로 `[{id, relevance 0|1|2}]`를 받는다.
   - Correct는 답한다. Ambiguous는 확인되는 부분만 답한다. Incorrect는 고정 문구 "포트폴리오 기록에서 찾지 못했어요"이며 생성 호출을 하지 않는다.
   - 최대 6개를 고르고, 조건부로 이웃 조각을 확장한다.
6. 인용 강제 생성을 구현하라(설계 3.6).
   - 가장 관련 높은 근거를 앞에, 두 번째를 끝에 두고, 질문은 앞과 뒤에 둔다.
   - 출력은 `{refused, sentences[{text, citations[]}], missing}`이다.
   - 서버 검사: 인용 id는 이번 근거의 부분집합, 문장당 1~3개. 위반 시 답 전체를 `CITATION_INVALID`로 실패 처리한다.
   - 인용은 요약 노드라도 원 첨부의 `파일명 · 위치`로 풀어 돌려준다.
7. 질문·답변을 **저장하지 마라**(설계 3.7). 서버에는 호출 로그 줄과 rate limit 카운터만 남긴다. 질문 길이와 사용자별 빈도를 제한하라.
8. 서비스 함수 `ask(user_id, question, filters)`를 8D의 API가 부를 수 있게 노출하라. 이 세션에서는 API·화면을 만들지 않는다.

범위 밖: API 라우트, 화면, 프로젝트 요약, 이전 기록 가져오기, 평가 세트 LIVE, HyDE의 기본 적용, pgvector·`pg_trgm`·외부 재정렬 API, 원본 HTML 변경.

## 검증

- **결정적 테스트(고정 임베딩 fixture)**:
  - 범위 고정: 사용자 3명 fixture에서 혼입 0건
  - BM25·RRF 순위 계산, 작은 코퍼스 우회의 경계값(전체 입력 기준)
  - 게이트 세 분기(Incorrect면 생성 호출 0회)
  - 인용 부분집합·개수 검사, `CITATION_INVALID`
  - 요약 노드 인용의 원 위치 풀기, 이웃 확장, rate limit
- **저장 없음**: 질문·답변이 DB와 로그에 남지 않아야 한다.
- **주입**: 첨부 속 지시 문장·링크 유도가 답을 바꾸지 않아야 한다(fixture 기준).
- **LIVE**: 소수 질문(D-A8 기록)으로 실제 Timely 경로(질문 임베딩·재정렬·생성)를 확인하고, 호출 수·소요·usage를 `docs/LIVE_TESTING.md`에 기록하라. 품질 판정은 8D에서 한다.
- 원본 HTML 9개 해시를 검사하고, 관련 결정적 테스트를 실행하라.

## 중단 조건

- 8B 미완료나 D-I1 미승인이면 BLOCKED로 보고한다.
- 노드 수 때문에 pgvector 등 인프라가 필요하다고 판단되면 측정 근거(설계 8절)와 함께 보고하고 멈춘다.
- 질문·답변 저장이 필요해 보이면 구현하지 말고 승인 요청으로 멈춘다.
- 같은 원인의 실패가 3회 반복되면 멈추고 원인·대안을 보고한다.
