# 8A단계 — 포트폴리오 RAG: 데이터 모델·수집 트리거·첨부 파일 추출 (AI 호출 없음)

## 목표

사용자가 투두에 **첨부한 파일**을 포트폴리오 코퍼스로 모으는 기반을 만든다. 완료된 본인 제출이 생기면 수집 작업이 멱등으로 만들어지고, 첨부 파일이 구조(쪽·슬라이드·시트·제목)를 유지한 블록과 조각으로 결정적으로 추출·분할된다. 이 세션에는 Timely 호출이 없다. 기술 기준은 `docs/RAG_DESIGN.md` 1·2.1·2.3·2.7·3.3(토큰화)·4절이다.

8단계는 `08A`(이 파일) → `08B` → `08C` → `08D` 순서로, 각각 새 세션에서 실행한다.

## 선행 게이트

- `docs/PRODUCT.md`의 **D-I1이 사용자 승인으로 기록**돼 있어야 한다. PROPOSED이면 시작하지 말고 BLOCKED로 보고한다. 보정된 항목은 이 프롬프트보다 승인 기록을 따른다.
- 5·6단계, D-H1, D-G1이 완료돼 있어야 한다. 이 프롬프트·D-I1·`docs/RAG_DESIGN.md`가 실행 브랜치에 병합돼 있어야 한다.
- 승인 뒤 다음 문서가 맞춰져 있지 않으면 첫 작업으로 맞춘다.
  - `docs/ROADMAP.md`: 8단계와 8A~8D 완료 조건
  - `docs/SECURITY.md`: 데이터 분류 `portfolio`(private, 본인만)

## 수행

1. `AGENTS.md`, `docs/HANDOFF.md`, D-I1, `docs/RAG_DESIGN.md`를 읽는다. 이어서 관련 코드를 읽는다: `src/moim/execution/`(`files.py`·`service.py`·`votes.py`), `src/moim/account/lifecycle.py`, `tools/ops_db.py`의 삭제 기록. 설계와 실제 코드가 다른 점을 먼저 보고하라.
2. `docs/RAG_DESIGN.md` 4절 테이블을 새 Alembic 마이그레이션으로 만들어라.
   - 모든 행에 `user_id`(users `ON DELETE CASCADE`)를 둔다.
   - 출처 열에는 그룹 테이블 FK를 걸지 않는다(I4).
   - 원본 파일 바이트와 질문·답변 테이블은 만들지 않는다. DB 확장도 만들지 않는다.
   - 마이그레이션은 마이그레이션 소유 역할이 실행하고, 런타임 앱 역할에는 7단계 역할 분리대로 필요한 조회·쓰기 권한만 준다.
   - downgrade는 이 단계가 만든 객체만 지운다.
3. 저장소 함수는 모두 `user_id`를 필수 인자로 받게 하라. 범위 없는 조회 함수를 만들지 마라.
4. 수집 트리거를 연결하라.
   - `completion`이 `DONE`이 되는 모든 경로(AI·TEAM·SELF·MANUAL)에서, **본인 기록이고 첨부 파일이 있을 때만** `portfolio_jobs`를 같은 트랜잭션에 멱등(`source_record_id` 유일)으로 만든다.
   - 프로젝트명·과제 설명·역할명·투두 제목·마감일을 그 시점 값으로 복사한다.
   - `되돌리기`로 완료가 사라지면 사본을 지운다.
   - 수집 입력에 넣지 않는 것: 다른 팀원 기록·첨부, 개인 AI 대화, MemberState, 인터뷰, 투표, 숨겨진 기준, 기준별 M2 이유.
5. 첨부 파일 추출을 구현하라(설계 2.1).
   - 형식별로 블록(`block_id`·`kind`·`locator`·`text`)을 만든다.
   - PDF 그림 쪽과 PPTX 삽입 이미지는 8B 대상으로 표시한다.
   - `python-pptx`·`openpyxl`을 런타임 의존성으로 추가한다. 파일은 기존 `check_file`·`_zip_check`를 다시 거친다.
   - HWP·HWPX는 파일명·메모만 색인한다.
   - 상한으로 잘린 사실은 `truncated`에 남긴다.
6. 분할을 구현하라(설계 2.3).
   - 구조 경계를 우선하고, 목표 약 250 cl100k 토큰, 상한 400, 겹침 0, 문장 미절단이다.
   - 400토큰 이하의 표·슬라이드는 통째로 둔다. `prev_id`·`next_id`를 저장한다.
   - `tiktoken`은 test extra에만 넣는다. fixture로 한국어 글자/토큰 비율을 재서 런타임 상수를 정하고, 측정값을 설계 9절에 기록한다.
7. 앱 측 BM25 토큰화(한글 음절 2-gram, 영숫자 소문자 단어)를 구현하고, 노드별 토큰 목록을 수집 때 저장하라(설계 3.3).
8. 작업 상태 기계(`QUEUED → EXTRACTING → DESCRIBING → UNDERSTANDING → EMBEDDING → READY | FAILED`)를 구현하라.
   - `fail_interrupted()`, 단계별 결과 저장, 실패 단계부터의 `다시 시도`를 기존 서비스의 `BackgroundTasks` 패턴으로 만든다.
   - 이 세션에서는 추출·분할까지만 실제로 돌린다. AI 단계는 결정적 테스트용 가짜 구현으로만 연결하고, LIVE로 보고하지 않는다.
9. 생명주기를 연결하라(I4, D-D1 D6·D7, D-G1).
   - 그룹 나가기·삭제는 사본을 지우지 않는다.
   - 계정 삭제는 포트폴리오 전부를 같은 트랜잭션에서 지운다.
   - D-G1 삭제 기록에 포함해 백업 복원 뒤에도 다시 지워지게 한다.
   - 사용자의 항목·프로젝트 단위 직접 삭제도 같은 경로를 쓴다.

범위 밖: Timely 호출(vision·요약·임베딩), 검색, 답변, API, 화면, 원본 HTML 변경.

## 검증

- **수집 트리거**: AI·TEAM·SELF·MANUAL 완료는 첨부가 있을 때 작업을 정확히 한 번 만든다. 첨부 없는 완료, REVIEWING·VOTING·REJECTED·WITHDRAWN은 만들지 않는다. 다른 팀원의 완료는 내 작업을 만들지 않는다. `되돌리기`는 사본을 지우고, 중복 완료는 멱등이어야 한다.
- **개인정보**: 심어 둔 private fixture(개인 AI 대화, MemberState, 인터뷰, 다른 팀원 첨부, `completion_criteria` 문장)가 블록·노드에 없어야 한다. 모든 저장소 함수가 `user_id` 없이 호출되면 실패해야 한다.
- **추출·분할**: 형식별 블록과 `locator`, 표·슬라이드 통째 보존, 문장 미절단, 겹침 0, 상한 절단 기록을 확인한다. ZIP 폭탄·확장자 위장·깨진 파일을 차단한다. 한국어 글자/토큰 측정값을 남긴다.
- **생명주기**: 그룹 나가기·삭제 뒤 사본 유지, 계정 삭제 뒤 전체 삭제, 직접 삭제, D-G1 복원 뒤 재삭제를 확인한다.
- **상태 복구**: 서버 재시작 뒤 실행 중 작업이 `FAILED`가 되고, `다시 시도`가 실패 단계부터 진행해야 한다.
- 원본 HTML 9개 해시를 검사하고, 관련 결정적 테스트를 실행하라.

## 중단 조건

- D-I1 미승인, 또는 승인 내용과 설계가 충돌하면 BLOCKED로 보고한다.

- 같은 원인의 실패가 3회 반복되면 멈추고 원인·대안을 보고한다.
