# 7단계 — 운영 준비

## 목표

MOIM을 운영 환경에 배포할 수 있는 수준으로 보안·복구·관측성·성능·비용을 검증하고 남은 위험을 증거 기반으로 판정한다.

## 선행 게이트

실제 운영 배포를 결정했을 때만 수행한다. MVP 완료 조건이 아니며 1~6단계가 끝나도 배포 전까지 미룬다. 1~6단계가 각 검증 게이트를 통과했고 모든 OPEN/BLOCKED와 사용자 승인 결정이 활성 문서에 반영돼 있어야 한다.

## 수행

1. 위협 모델과 ASVS 기반 점검으로 인증, 객체 인가, 그룹 경계, private 데이터, 파일, AI 경계를 검토하라.
2. TLS, 비밀 관리, 최소 권한, 암호화 백업, 마이그레이션/롤백, 복구 절차를 준비하라.
3. 백업 복원 리허설과 장애/AI 작업 실패 대응 훈련을 수행하라.
4. 구조화 로그·메트릭·경보에 민감정보가 없고 operation/request 상관관계가 유지되게 하라.
5. 현실적인 부하 표본으로 latency·오류율·DB 병목·Timely 비용을 측정하고 표본 한계를 명시하라.
6. RLS와 악성 파일 검사 필요성을 실제 위협/운영 환경 근거로 결정하라.

범위 밖: 근거 없는 주요 인프라 교체, 승인 없는 LIVE/비용 증가, 기능 추가, 원본 HTML 변경.

## 검증

- 전체 결정적 테스트, 마이그레이션, 원본 HTML 해시, 1440×900 스크린샷 캡처를 깨끗한 환경에서 실행하라.
- 복원된 DB로 핵심 사용자 흐름과 private 경계를 재검증하라.
- 보안 스캔 결과는 오탐 판정 근거와 함께 기록하고 고위험 미해결을 숨기지 마라.
- LIVE 검증은 승인된 예산만 사용하고 호출 수·latency·usage·오류를 기록하라.

## 중단 조건

고위험 보안 결함, 복원 실패, 데이터 손실 가능성, 필수 외부 권한 또는 승인 없는 비용이 있으면 출시 준비를 PASS로 판정하지 않는다.

## 완료 보고

출시 판정(PASS/CONDITIONAL PASS/FAIL), 검증 증거, 잔여 위험과 담당 조치, 범위 밖 항목, 다음 한 단계만 보고하라.
