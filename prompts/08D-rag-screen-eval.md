# 8D단계 — 포트폴리오 RAG: 마이페이지 화면·API·품질 평가

## 목표

8A~8C의 RAG를 마이페이지 `포트폴리오` 탭으로 사용자에게 보여 준다. 화면은 **원본 `moim-mypage.html`의 기존 마크업과 CSS 클래스만** 조합해 만들고, 디자인을 크게 벗어나지 않는다. 이어서 미리 고정한 합격 기준으로 RAG 품질을 판정하고 8단계를 닫는다. 기술 기준은 `docs/RAG_DESIGN.md` 7·10절이다.

## 선행 게이트

- `08C-rag-retrieval.md`가 완료되어 `docs/HANDOFF.md`에 기록돼 있어야 한다. 아니면 BLOCKED로 보고한다.
- D-I1과 화면 v2 결정 D-I2(I7 개정)가 승인 상태여야 한다.
- 시험 세트 LIVE(약 360회 + 요약 출력 약 10회)는 D-A8에 따라 실행 전에 사용자 사전 승인이 필요하다.

## 수행

1. API를 구현하라.
   - 로그인·CSRF·`action_id` 멱등을 적용하고, 다른 사용자 항목은 404로 답한다.
   - 엔드포인트: `GET /api/portfolio`, `GET /api/portfolio/projects/{id}`, `POST /api/portfolio/jobs/{id}/retry`, `POST /api/portfolio/projects/{id}/summary`, `POST /api/portfolio/summary`(포트폴리오 정리, D-I2), `POST /api/portfolio/query`(8C `ask`, 전체 또는 `project_id` 범위, 응답에 근거 원문 포함), `POST /api/portfolio/import`, 항목·프로젝트 `DELETE`.
   - 응답에 넣지 않는 것: 숨겨진 기준, 다른 사용자 데이터, 임베딩, 서버 경로, 프롬프트, 색인 머리말·LLM 맥락.
2. 요약을 구현하라(설계 2.5.1·2.5.2).
   - 프로젝트 요약: 맡은 일·만든 결과·배운 점 스키마, 문장마다 근거 1~3개.
   - 포트폴리오 정리: 소개 문장 1~3개와 역량 칩 0~8개. 역량 숫자는 서버가 근거 문서 수로 센다.
   - 두 요약 노드를 같은 검색 풀에 넣는다. 처음은 `만들기`, 이후 `다시 만들기`만 둔다. 새 첨부가 READY가 되거나 프로젝트가 바뀌면 "오래됨"으로 표시하고 자동 재생성은 하지 않는다. 인용 검사 실패는 `CITATION_INVALID`로 보여 주고 이전 요약을 유지한다.
   - 근거 원문 발췌(서버가 자른 200자)와 고정 추천 질문·거절 대안(결정적)을 설계 3.6대로 구현한다.
3. 이전 기록 가져오기를 구현하라(I6). 원본 첨부가 아직 있고 현재 활성 구성원인 본인 완료 기록만 대상이다. 예상 호출이 100회 이상이면 실행하지 말고 승인 요청으로 보고한다.
4. 화면을 구현하라(D-I2, 설계 10절 v2 대응표와 10.1 제약). 시안은 `docs/design/portfolio-v2/index.html`이다.
   - `templates/mypage.html`에 다섯 번째 탭 `포트폴리오`를 추가한다. 탭 버튼은 기존 `role="tab"`과 같은 선 스타일의 18px SVG를, 본문은 `card deco`와 `ring`·`crew`를 쓴다.
   - 개요: `AI 정리` 줄, 나를 소개하는 세 문장, 근거로 확인된 역량(`ul.rules > li.ok`), 프로젝트 목록(`ul.groups > li.grp` + `.prog` 진행 막대), 전체 질문창과 추천 질문, `이전 기록 가져오기` 줄.
   - 상세: 한 줄 `p.sub`, `AI 정리` 줄, 맡은 일·만든 결과·배운 점 `.row`, 근거 자료 `li.grp`, 프로젝트 질문창, `목록으로`.
   - 답변: 문장마다 `span.dd`(`근거 n`), 근거 확인 `li.ok`, 근거 원문 `.row` + `span.lock`. 출처 표기는 `span.dd`를 쓰고 `.row` 안에서는 `<b>`를 넣지 않는다(10.1).
   - **새 CSS 클래스·색·글꼴 크기·카드 모양을 만들지 마라.** 대응표에 없는 요소가 필요하면 구현하지 말고 제품 차이로 보고하라.
   - 빈 상태·로딩·오류·`다시 시도`·거절 문구를 넣는다.
   - 모든 사용자·AI 문자열은 textContent로 그리고, 인라인 스크립트는 넣지 않는다. 원본 HTML은 수정하지 마라.
5. 평가 세트를 만들고 합격 기준을 고정하라(설계 7절).
   - fixture 코퍼스(사용자 3명의 첨부 파일), 개발 세트 30문항, 시험 세트 120문항을 `tests/`에 둔다.
   - **LIVE 실행 전에** 설계 7.2 기준표를 그대로 커밋하고, 결과를 본 뒤 낮추지 않는다.
   - 결정적 테스트(설계 7.3)를 먼저 통과시킨다.
6. 개발 세트 LIVE(실제 Timely, 약 90회)로 튜닝하라. 조정 순서는 설계 7.2를 따르고, 바꾼 값과 근거는 설계 9절에 남긴다.
7. 사용자 사전 승인 뒤 시험 세트 LIVE를 한 번만 실행하라.
   - 결과는 지표별 값, 신뢰구간(질문 단위 Wilson, 문장 단위 지표는 질문 단위 bootstrap), 판정자 일치율이다.
   - 사람 라벨이 150개 미만이면 인용·충실도 지표는 "판정 보류(참고값)"로 표시한다.
   - 결과를 `docs/LIVE_TESTING.md`에 기록하라.
8. 문서를 갱신하라. 대상은 `docs/ARCHITECTURE.md`, `docs/SECURITY.md`, `docs/LIVE_TESTING.md`, `docs/OPERATIONS.md`(작업 실패 대응·호출 수 추정), `docs/RAG_DESIGN.md` 9절, `docs/ROADMAP.md`, `docs/HANDOFF.md`다.

범위 밖: 외부 공유·공개 페이지·내보내기, 질문·답변 저장, 새 디자인 시스템이나 새 카드 스타일, 원본에 없는 레이아웃, 원본 HTML 변경.

## 검증

- **API 보안**: 교차 사용자 404, CSRF, `action_id` 멱등, rate limit, 응답에 숨겨진 기준·임베딩·경로가 없음을 확인한다.
- **화면 안전**: XSS 파일명·첨부 속 스크립트 문자열이 textContent로만 그려지고, 첨부 속 URL이 클릭 가능해지지 않아야 한다.
- **화면 상태**: 빈 상태·로딩·오류·`다시 시도`·거절·새로고침 복구를 확인한다.
- **디자인**:
  - 원본 HTML 9개 해시가 기준과 같아야 한다.
  - 구현본 CSS에 새 클래스·색이 추가되지 않았음을 diff로 확인한다.
  - 구현 화면이 시안 `docs/design/portfolio-v2/index.html`과 구조가 같고, 10.1의 제약(버튼 두 줄 접힘·`crew` 겹침·`.row b` 깨짐 없음)을 지키는지 확인한다.
  - 1440×900 스크린샷(포트폴리오 개요·상세·답변(근거 원문 포함)·거절·빈 상태·오류, 긴 화면은 같은 폭으로 이어서)을 원본 `moim-mypage.html`의 `참여 중인 그룹`·`계정 관리` 탭과 나란히 캡처해, 사용자가 눈으로 확인하게 한다.
- **품질(LIVE)**:
  - 시험 세트에서 설계 7.2의 고정 기준을 판정한다: 혼입 0, Recall ≥ 0.85, 1단계 실패율 ≤ 0.08, 올바른 거절률 ≥ 0.90, 잘못된 거절률 ≤ 0.15, 주입 fixture 10/10, 인용 형식 1.00(요약 출력 포함, 설계 7.2). 인용 재현율·정밀도·충실도는 사람 라벨 규칙을 따른다.
  - 주입 fixture 통과는 완전 방어를 뜻하지 않는다고 보고에 적는다.
  - 기준 미달은 FAIL로 보고한다.
  - fixture·mock 결과를 LIVE로 보고하지 마라. p95를 주장하지 마라.
- 단계 종료 때 전체 결정적 테스트와 `prompts/VALIDATION.md` 교차 단계 회귀를 실행하라.

## 중단 조건

- 8C 미완료나 D-I1·D-I2 미승인이면 BLOCKED로 보고한다.
- 설계 10절 대응표에 없는 화면 요소, 새 CSS, 원본과 다른 레이아웃이 필요하면 구현하지 말고 제품 차이 승인 요청으로 멈춘다.
- 시험 세트 LIVE와 이전 기록 가져오기는 100회 이상이면 사전 승인 없이 실행하지 않는다.
- 합격 기준을 낮춰야만 통과할 수 있으면 낮추지 말고 FAIL과 원인 분석을 보고한다.
- 같은 원인의 실패가 3회 반복되면 멈추고 원인·대안을 보고한다.
