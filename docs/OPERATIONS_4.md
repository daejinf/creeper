## 수정한 문제와 재검사 근거

1. **B→C 계약 불일치:** 역할 `member_id/role` 배열을 ID→역할 객체로 정규화합니다. 서로 다른 중복 역할은 임의로 합치지 않습니다. 알려진 체크인 객체도 문자열 목록으로 바꿉니다.
2. **한 카드 오류가 전체를 중단:** 변환 불가능한 값은 해당 카드의 `previous_value`에 남기고 미정·검토 대상으로 표시합니다. 정상 카드·대화·이전 성공은 유지합니다.
3. **E의 답변과 상태 불일치:** 구조화 추출을 필수로 요구하고, 명시적 주간 시간은 근거 있는 정수 분으로 보존합니다. 경험을 말했는데 구조화하지 않은 응답을 정상 완료로 통과시키지 않습니다.
4. **세부 모름이 기존 사실을 삭제:** `state.refinements`·`refinement_states`에 따로 기록합니다. '화면 두 개'는 유지하고 '결과물 수준 모름'만 별도로 미정입니다. 이 상태는 본인 범위입니다.
5. **주간 예산과 주차 불일치:** 시작일부터7일 단위 구간과 구간별 합계 한도를 모델에 전달합니다. 검증기 한도를 낮추거나 오류를 무시하지 않습니다.
6. **요일 오류:** 코드 달력을 코칭에 제공하고 한국어 날짜·요일 표기도 검사합니다. 날짜를 임의로 바꾸지는 않습니다.
7. **화면 초기화:** 첫 내장 브라우저에서는 모듈 메뉴가 비고 JS 초기화 오류가 났습니다. 서버 소스와 받은 구버전 JS의 줄 수가 달랐습니다. 캐시 혼입 가능성을 줄이도록 버전 있는 자산 URL과 no-store를 적용한 뒤 정상 초기화·기록 복원을 직접 확인했습니다.
8. **개인 대상 전환:** 다른 닉네임을 고른 직후 이전 개인 내용이 잠깐 남는 문제를 발견했습니다. 전환 시작과 동시에 폼·결과·요청 JSON을 숨기고, 올바른 본인 기록을 받은 뒤 표시합니다. 실제 브라우저에서 이전 폼/결과 hidden 상태와 다른 구성원의 빈 조건을 확인했습니다. 이 대상 선택은 서비스 인증을 대신하지 않습니다.
9. **독립 E→F 비교 조건:** 공동 계획 D 없이 개인 계획을 생성했어도, 저장된 본인 계획의 공개 문맥을 F에 함께 전달합니다. 날짜를 바꾼 계획이 목표 비교에서 걸리는 회귀 검사를 추가했습니다.
10. **읽기 어려운 결과:** 확인 일정·실행 횟수·역할·주요 일정의 한국어 이름, 닉네임·공개 범위 설명을 표시합니다. raw JSON은 개발자 상세에 유지합니다. 미정 역할의 자리표시는 실제 사실값으로 사용하지 않습니다.

최종 자동 검사 **121개**, 실패0.200개 시나리오의 형식·연결 데이터 검사도 통과했습니다. 이번에200개 전부를 LIVE 운영한 것은 아닙니다.

## 사용량·낭비 방지

이번 네 운영과 실패 부분 재검사에 실제 HTTP **26회**를 사용했습니다. 처음 제한 범위에서 사용한9회도 포함한 수치이며, 그 뒤 추가한 수치를 중복 합산하지 않았습니다. 사용자 추가 허용 후 안전 상한40회 중 필요한26회에서 종료했습니다. 이전3회 평가21회 및 더 이전0.11의116회와 별개입니다.

확인 가능한 토큰은 **96,013 이상**입니다. 평가 도구가 새 호출에 기존 action ID를 재사용해 저장 충돌한1건의 응답·토큰은 보관하지 못했습니다. 실제 HTTP는 예산에 차감됐습니다. 이를 숨기거나 토큰을 추정하지 않습니다. 결과를 먼저 파일에 보존하고 새 AI 실행에는 새 action ID를 사용하도록 도구를 수정했습니다. 프로덕션 저장소는 서로 다른 결과로 같은 동작을 덮어쓰는 것을 올바르게 거부했습니다.

성공한 동일 공동 계획은 보존했고, 단순 형식 표시 수정은 저장 응답 REPLAY로 확인했습니다. CACHE/REPLAY/CODE를 LIVE로 세지 않습니다. 열기·복원·화면 전환·검토에는 모델을 호출하지 않습니다.

## 화면에서 직접 확인

테스트 화면의 기록 메뉴에 다음 네 개가 있습니다. 합성 자료만 들어 있으며 열기는 무료입니다.

- 운영1 · 공동 목표 연결 검증
- 운영2 · 개인 조건·계획 검증
- 운영3 · 마감일 변경·새 버전
- 운영4 · 공부 분석·실패 복원

네 화면의 캡처와 실제 요청·응답·검증·실패 원본은 로컬 `runtime/operations-4/`에 있습니다. 사용자 DB·개인 원문·API 키는 배포 wheel에 포함하지 않습니다. 캡처에서 레이아웃 잘림은 발견하지 않았지만 긴 과제 목록의 스크롤 부담은 남습니다. 화면은 운영 서비스가 아닌 개발자 모듈 실행기입니다. 스크린샷만으로 전체 접근성 준수를 판정하지 않습니다.

## 남은 한계

- 네 합성 사례의 에이전트 검토입니다. 실제 SW팀이 처음부터 README만 따라한 사람 인수나 대규모 의미 품질 평가를 대신하지 않습니다.
- 주간 총량은 검증하지만 요일별 작업 가능 시간까지 완전히 배치하지 않습니다. 개인 사유는 공개 생성에서 제외하고 한계를 경고합니다.
- 개인정보 표식의 공개 결과 혼입은 없었지만, 우회 표현의 의미적 누출까지 모두 증명한 것은 아닙니다.
- `OBJECTIVE_ONLY`는 공개 범주의 enum입니다. SW는 '완료 여부만' 같은 세부 동의 원문도 저장하고, 이를 모든 객관적 지표 공개 허용으로 확대하지 않아야 합니다.
-401은 주입 장애입니다. 실제 키를 바꾸거나 사용자 계정 장애를 만들지 않았습니다. 디스크 장애와 서버 종료가 동시에 발생한 미저장 메모리는 복구를 보장하지 않습니다.
- F의 valid는 주어진 범위의 코드 검사 통과입니다. 최종 사용자 확인·권한·그룹 승인·의미 검토는 별도입니다.

## 전달·정리
