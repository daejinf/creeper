# M0/M1 PostgreSQL 통합 운영 검증 — 0.15.0

검증일: 2026-11-05. **로컬 PostgreSQL 통합 저장은 검증 완료, AI 내용은 사용자 검토를 전제로 한 조건부 사용**입니다. 사람 검토·SW팀의 직접 인수·운영 서비스 권한 검증을 완료했다고 표시하지 않습니다.

## 구현한 범위

- 대화·개인 문답·입력·실행 상태·수정/확인·공동/개인 목표·계획·과제·평가 기준을 PostgreSQL 한 곳으로 통합.
- 앱 전용 계정 `wemeet_app` 생성. SUPERUSER/CREATEDB/CREATEROLE 권한 없음. DDL·스냅샷 UPDATE/DELETE·권한 부여 없음.
- 동작 ID·입력 해시·기록 revision·DB 행 잠금으로 중복 실행과 충돌 처리. 모델 응답을 기다릴 때 DB 트랜잭션을 유지하지 않음.
- 응답 수신 후 저장 실패 시 Fernet 암호화 파일에서 저장만 재시도. 불확실한 실행을 자동 유료 재호출하지 않음.
- 결과·정식 목표/계획/과제·현재 포인터를 같은 트랜잭션으로 저장. 잘못된 확인값은 실패 이력으로 기록.
- 개인 기록 소유자도 DB 외래 키로 그룹 구성원에 연결. 공개·본인·서비스 내부 조회 범위 분리.
- M1-A~F 독립 함수 유지. `PostgresRecordStore`·`ExecutionAdapter`는 선택적 어댑터이며 M0/M1 코어가 DB를 직접 읽지 않음.

LIVE는 **완료된 모듈 실행 66건, 실제 HTTP 총68회, 총223,613토큰**입니다. 재시도·보정과 내용 보완을 포함하며 120회 상한 안에서 수행했습니다. 성공 결과의 코드 재사용과 저장 재시도는 이 수에 더하지 않았습니다. 이 값은 provider 응답과 실행 계수이며 청구 금액을 추정한 값이 아닙니다.

보완된 걷기는 8명 모두 서로 다른 날짜 4회, 첫 구간2회·둘째 구간2회, 마지막 날 추가 걷기 없음이 확인됐습니다. 표기의 ‘셋째 주’ 오기와 공개 범위 문구 7곳은 에이전트가 새 버전으로 수정했습니다. 날짜·분량을 임의 확정한 사람 승인으로 집계하지 않습니다. **검토 주체는 에이전트이며 실제 사용자 승인도 아닙니다.**

최종 17명의 평가 기준은 익명 시나리오의 **모의 확인**입니다. 실제 서비스의 그룹 승인·활성화·알림·벌점은 실행하지 않았습니다. 과거 계획과 기존 기준은 그대로 남고 신규 기준은 현재 계획을 참조합니다.

## 발견·수정한 결함

1. 개인정보 마스킹이 일부 SHA256을 전화번호로 오인: 단어 경계를 수정하고 정확한 해시 보존을 회귀 검사했습니다.
2. `milestones` 누락과 빈 목록을 다르게 비교해 중복 공동 버전 연결: 기본값을 정규화하고 역할·빈도·운영 조건도 비교합니다. 이미 저장된 관계는 변경하지 않고 새 버전으로 복구했습니다.
3. 외부 runner의 미확인 프로필이 영구 저장 재시도 상태가 됨: 경계에서 `RESULT_VALIDATION_FAILED`로 기록합니다.
4. DB 실패가 웹에서 REVISION_CONFLICT로 바뀜: 실제 503·SAVE_ONLY를 보존합니다. 실행 중인 동작 ID를 화면이 새 ID로 바꾸지 않습니다.
5. 과거 `sync_attempts` 실패가 현재 원자적 저장 성공을 가림: 현재 journal/operation 상태를 기준으로 표시합니다.
6. AI 내용의 부분 주차·담당 범위가 불명확: 확인 조건을 추가하고 영향을 받는 계획만 보완했습니다. API 성공을 내용 품질 성공으로 바로 집계하지 않았습니다.

## 이관과 남은 경계

기존 SQLite 11개 기록의 메시지·입력·결과 JSON을 해시 대조했습니다. **9개 정상·2개 보류**이며 원문·실행 이력을 삭제하거나 가짜 사실로 고치지 않았습니다. 보류 기록은 현재 기준과 새 실행에서 제외합니다. SQLite 파일은 읽기 전용이며 정상 서버에 fallback 경로가 없습니다.

데이터베이스에는 검사용 namespace의 합성 자료도 있습니다. 전체 DB 테이블 수량을 실제 운영 그룹 수로 해석하지 마세요. LIVE 사례 수는 위의 4개로 한정합니다.

외부 API의 정확히 한 번 실행, 자연어 계획의 모든 의미적 일치, 다중 서버 복구 파일 공유·키 관리·실제 로그인 권한은 이번 로컬 검사만으로 보장하지 않습니다. SW는 인증 결과로 group/owner 범위를 정하고, 복구 파일과 키의 운영 보관 정책을 연결해야 합니다. 사람의 최종 의미 검토와 SW팀 직접 인수는 검증 대기입니다.
