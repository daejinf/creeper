# SECURITY

위협 모델, 데이터 분류, 보관·삭제와 테스트 매트릭스. 보안 원칙(인증, 인가, CSRF, 출력 인코딩, 비밀번호·쿠키·토큰, rate limit, AI 접근 권한)의 문장은 `AGENTS.md` 헌법 영역 `2. 변경 불가 원칙`의 `보안` 항목이 단일 원본이며 여기서 복제하지 않는다. AI 호출 로그 규칙은 `docs/LIVE_TESTING.md`를 따른다.

## 1. 데이터 분류

분류 정의는 `AGENTS.md` `개인정보` 항목을 따른다. 이 표는 구현 때 저장 위치를 정하는 기준이다.

| 분류 | 예 | 열람 | 로그 |
|---|---|---|---|
| private conversation | 개인 AI 대화 | 해당 사용자만 | 원문 금지 |
| private profile/state | MemberState, 1·2·3순위 원문, 제약 조건 | 해당 사용자만 | 원문 금지 |
| confirmed assignment | 사용자가 확정해 공유한 역할·투두 | 그룹 구성원 | 메타데이터만 |
| team artifact | ProjectBrief, 확정 역할·투두 기반 실행 기록 | 그룹 구성원 | 메타데이터만 |
| 숨겨진 평가 기준 | 투두의 `deliverable`·`completion_criteria` | 서버만 (화면은 제목·기한만) | 원문 금지 |
| 비밀정보 | 비밀번호 해시, 세션, API 키 | 서버만 | 금지 |

## 2. 위협 모델 (초안, 단계별로 보강)

| 위협 | 대응 방향 | 시작 단계 |
|---|---|---|
| 다른 사용자·그룹 데이터 접근(IDOR) | 모든 조회·변경에 인증 + 객체 단위 인가 + 그룹 경계 | 1 |
| 개인 대화·상태 노출 | 서버 쿼리 수준 격리, 응답 모델에서 private 필드 제외 | 3 |
| 순위 원문 노출(배정 안내 문구) | GATE B에서 문구 승인 전까지 타 구성원 이름·순위 비노출 | 3·4 |
| XSS(사용자 입력·AI 출력) | 템플릿 자동 이스케이프, `textContent`. 원본의 `innerHTML` 데모 렌더링은 복사하지 않음 | 모든 단계 |
| CSRF | 상태 변경 요청마다 토큰 검증 | 1 |
| 계정 열거·무차별 대입 | 중복 확인·로그인 rate limit, 동일 응답 | 1 |
| 프롬프트 주입 | 사용자 입력은 자료로만 취급하고 AI 출력은 권한 결정에 쓰지 않음 | 3 |
| 비밀정보·원문 로그 유출 | 메타데이터만 로깅, 키는 서버 환경에서만 사용 | 0B-2 |
| 첨부 파일 악용 | 형식·크기 검증은 GATE D 이후, 악성 파일 검사는 7단계 | 5 |

## 3. 보관·삭제

OPEN. 그룹·계정 탈퇴와 데이터 삭제·익명화·보관 정책은 GATE D 승인 전까지 정하지 않는다. 승인 없이 사용자 데이터를 삭제하거나 되돌리기 어려운 마이그레이션을 하지 않는다.

## 4. 결정적 테스트 매트릭스

LIVE 테스트로 대체하지 않는다. 해당 기능이 생기는 단계에서 추가한다.

| 대상 | 시작 단계 |
|---|---|
| 인증·인가와 교차 사용자·교차 그룹 접근 차단 | 1 |
| private 데이터 격리 | 3 |
| CSRF, 입력 검증과 XSS | 1 이후 매 단계 |
| 상태 전이, STALE, revision과 멱등성 | 2 이후 |
| DB 저장·복원 | 0B-1 이후 |
| 오류, 타임아웃과 새로고침 복구 | 0B-3 이후 |

### 4-1. 0B-3 현황과 남은 보안 항목 (2026-11-18)

- 통과: 작업 상태의 DB 저장·복원, 서버 재시작 뒤 실패 표시, 재시도, 중복 요청, revision 충돌, 새로고침 복구(`tests/test_jobs.py`).
- **작업 API(`/api/jobs`)에는 인증, 객체 단위 인가, CSRF가 아직 없다.** 핸들러가 하나도 등록되지 않으면 모든 `kind`가 422이므로 지금은 아무 작업도 만들 수 없다. 1단계 이후 첫 핸들러를 등록하는 단계에서 다음을 함께 넣어야 한다: 로그인 필요, 작업 소유자(또는 그룹) 검사로 다른 사용자의 `status_url` 조회·재시도 차단, CSRF 토큰, `input`의 스키마별 검증. `job_id`는 UUID라 추측하기 어렵지만 인가를 대신하지 않는다.
- 작업 `input`은 사용자의 private 입력일 수 있다. DB에는 저장하되 응답·로그에 나가지 않게 했다(테스트로 확인). 보관·삭제 정책은 6단계에서 정한다.

### 4-2. 1단계 인증 현황 (2026-11-18)

구현은 `src/moim/auth/`, 검증은 `tests/test_auth.py`(결정적, LIVE 없음).

| 항목 | 구현 값 |
|---|---|
| 비밀번호 | Argon2id(argon2-cffi 기본값, RFC 9106 low-memory). 8~128자, 영문·숫자 포함. 앞뒤 공백을 자르지 않음. 로그인 때 `needs_rehash`면 다시 해시 |
| 세션 | 서버 측 `auth_sessions`. 쿠키에는 난수 토큰(32바이트)만 있고 DB에는 sha256만 저장. 로그인 유지 해제: 브라우저 세션 쿠키, 유휴 2시간, 절대 12시간. 유지: 유휴 14일(서버가 강제), 절대 30일(쿠키 `Max-Age`도 30일). 유휴 만료는 1분에 한 번만 연장. 로그인할 때 제시된 기존 토큰을 폐기하고 새 토큰 발급(세션 고정 방지), 로그아웃은 서버 행 삭제 |
| 쿠키 | `HttpOnly`, `SameSite=Lax`, `Path=/`. 운영(`MOIM_ENV=production`)은 `Secure`와 `__Host-` 접두, HSTS. 개발·테스트의 로컬 HTTP만 `Secure` 예외 |
| CSRF | 모든 상태 변경 POST(`/api/auth/*`)에 이중 제출 토큰(HttpOnly 쿠키 + `X-CSRF-Token`)과 `Origin`·`Sec-Fetch-Site` 검사. 로그인·로그아웃 때 토큰 교체. 운영의 `__Host-` 접두로 하위 도메인이 토큰을 심을 수 없다 |
| rate limit | DB 테이블 `auth_throttle`(프로세스와 재시작에 무관, 원문 아이디·주소 대신 해시 키). 로그인 실패: (아이디+주소) 15분 5회, 주소 15분 20회, 아이디 15분 15회 → 15분 잠금. 잠금 중에는 올바른 비밀번호도 429. 중복 확인: 주소당 10분 30회. 회원가입 시도: 주소당 1시간 10회 |
| 계정 열거 | 로그인 실패 응답은 아이디 없음·비밀번호 틀림이 같은 상태·본문·헤더이고, 없는 아이디도 Argon2 검증 시간을 소모. 없는 아이디도 같은 규칙으로 잠긴다. **중복 확인 버튼 자체가 아이디 존재를 알려주는 기능이므로**(원본 디자인) 열거를 막지 못하고 rate limit으로만 늦춘다 |
| 입력 | 이름 NFC·공백 정리·제어/서식 문자 거부·30자, 아이디 NFKC 정규화 후 `^[a-z0-9]{4,16}$`와 예약어, 요청 본문 8KB 상한(Content-Length 없는 스트림 포함), 알 수 없는 필드 거부 |
| 출력 | Jinja 자동 이스케이프. 정적 JS는 `textContent`만 쓰고 저장소·`document.cookie`·`innerHTML`을 쓰지 않는다(테스트가 검사). 인라인 스크립트·이벤트 핸들러 없음 |
| 헤더 | 모든 응답에 CSP(`script-src 'self'`, `frame-ancestors 'none'`, 스타일은 인라인과 Google Fonts 허용), `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`. 인증 페이지·API는 `no-store`, 정적 파일은 `no-cache`(재검증) |
| 로그 | `moim.auth`는 이벤트와 `user_id`만 기록. 아이디·비밀번호·토큰은 기록하지 않는다(테스트가 검사) |

남은 제한:

- 클라이언트 주소는 `request.client.host`만 쓴다. 리버스 프록시 뒤에서는 모든 사용자가 한 주소로 보이므로 프록시 신뢰 설정이 필요하다(7단계).
- 아이디 단위 잠금(15분 15회)은 여러 주소에서 의도적으로 실패시키는 공격으로 특정 계정의 로그인을 15분 막을 수 있다. 외부 계정 없이 가능한 완화는 주소·계정 쌍 잠금뿐이며 MVP에서 이 위험을 받아들였다.
- 비밀번호 복구는 제공하지 않는다(ROADMAP 기본 정책). 화면에 지원하지 않음을 표시한다. 비밀번호를 잊으면 계정을 되찾을 방법이 없다.
- 계정 탈퇴·삭제·비밀번호 변경은 범위 밖이다(6단계, GATE D). 사용자별 전체 세션 폐기 함수(`SessionStore.revoke_all`)만 준비돼 있다.
- `/api/jobs`에는 아직 인증이 걸려 있지 않다. 재사용할 `require_user`·`verify_csrf`(`auth/deps.py`)가 준비됐고, 첫 핸들러를 등록하는 단계에서 반드시 적용한다.

## 5. OPEN (기술 검증으로 정함)

CSP 세부값은 인증 화면 기준으로 4-2에 기록했다. 이후 화면(채팅·첨부)에서 필요가 생기면 4-2를 개정한다. 개인정보·비용·주요 의존성에 영향을 줄 때만 사용자 승인을 요청한다.
