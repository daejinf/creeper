# 0.15.0 PostgreSQL 통합 검증

최신 범위와 수치는 [통합 운영 보고서](POSTGRES_OPERATIONS.md)를 참고하세요. 아래 기록은 이전 버전의 역사이며 최신 성공 결과로 합산하지 않습니다.

> 이 문서는0.12.0의 이전3회 평가입니다. 최신0.12.1은 [4회 실제 운영·수정 보고서](OPERATIONS_4.md)를 보세요.

# 0.12.0 검증 기록

검증일 2026-11-04 · 에이전트 검토. **SW팀 직접 인수와 사람의 내용 검토는 수행하지 않았습니다.**

판정: 개발자 시험 연동은 조건부 사용 가능. 대규모 AI 내용 품질의 인수 완료로 표시하지 않습니다.

## 정확히 3회 평가·수정·재검사

| 회차 | 발견·수정 | 재검사 | LIVE HTTP |
|---|---|---|---:|
| 1 | 새로고침 기록 유실·수동 JSON 연결, 날짜/완료 기준 혼동 | 자동 검사103개, 저장·B 준비 브라우저 | 6 |
| 2 | 저장 큐 충돌·모드/대상 복원·새 개인 답변 차단·F 내부 의존성 | 자동 검사107개, C→D→E 세 답변→계획→F·새로고침 | 7 |
| 3 | 단독 E 입력 준비의 부작용·B 제안 혼입·C 사실 누락·실패 재실행 | 자동 검사112개·독립 설치·4개 화면 폭·서버 재시작 | 8 |

3회차8회에는 최초5회와 실패 내용 영향을 받은 B/C 재검사3회가 포함됩니다. 별도의4회차를 실행하지 않았습니다. 재시도·보정 포함 **신규 HTTP21/30**, 확인된 사용량 **54080 tokens**입니다. 이전0.11의116회와 별개입니다. 청구 비용은 추정하지 않습니다.

각 회차 최초5개 모듈 결과는 API/계약상OK였으나, 내용 검토에서 발견한 결함을 수정했습니다. **API 성공=내용 합격이 아닙니다.** 같은3종 합성 사례를 비교했으며200개를 LIVE 재평가한 것이 아닙니다. 회차별 원본·소스 해시·추가 검토는 로컬 runtime/evaluation-012/round-1~3에 구분 보관합니다.

## 최종 로컬·설치·화면

- 단위·계약·독립성·실패 복구·개인 범위 검사112개 통과, 실패0. FastAPI TestClient 의존성의 폐기 예정 경고1종은 제품 오류가 아닙니다.
- 200개 시나리오 데이터 검사 통과: 기본100/변형100, 분야10종, 평가 분리 유지. LIVE 품질 증거와 구분합니다.
- 390/768/1024/1440px ×8개 독립 작업32회 fixture 검사 통과. 가로 넘침·JS 오류0. C 수정값 보존, E 세 번째 답변과 A 중복 클릭 무호출 검사 포함.
- 실제 서버 종료·재시작 뒤 합성 기록의 공개 대화·개인 대상·F 결과·FIXTURE 모드 복원. 모델 요청0. 화면 폭 검사와 같은 DB를 사용해 바뀐 선택 단계는 별도 체크포인트를 저장한 뒤 확인했습니다.
- 별도 venv에 최종 wheel과 선언 의존성만 설치. FastAPI 미설치·소스 경로 없이6개 독립 예제와 기록 저장→종료·복원→공동·개인 계획→F 예제 통과.
- 현재 코드로3회차 저장 응답8개 REPLAY 검사 통과, 신규 HTTP0. 과거 실패 원본을 성공으로 덮어쓰지 않았습니다.

## 내용 검토의 한계

A는 구체적인 실행안을 제시했지만 확정을 가볍게 권하는 표현이 남았습니다. B 재검사에는 불필요한 중국어 단어가 섞인 문장이 있었으며, 추천·미확인 상태로 유지했습니다. 코드만으로 문장 의미·개인정보의 우회 표현을 완전히 검증하지는 못합니다. 실제 사용자 확인·사람 검토가 필요합니다.

디스크 저장 실패 시 생성 응답은 화면과 같은 서버 프로세스에서 보존합니다. 서버까지 종료되면 미저장 메모리는 복구되지 않습니다. 공급자 호출의 완전한 exactly-once를 보장하지 않습니다.

이번 LIVE는3종 소규모 합성 사례입니다. 과거 마감일 변경 승인 문제와 개인 범위·수정값 보존은 코드 검사로 확인했으나, 모든 실제 사용 상황이 검증된 것은 아닙니다. 중대한 재현 결함이 새로 나오면 해당 경로 인수를 보류해야 합니다.

이전0.11 평가·배포 원본은 저장소 밖 보관본에198개 파일의 SHA256 검증 후 정리했습니다. 현재 기록 SQLite는 삭제하지 않았습니다. 상세 통계·소스 해시는 verification-summary.json을 참고하세요.
