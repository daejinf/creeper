# 모듈을 수정하면 화면에도 반영되나요?

## 이 작업 폴더에서 실행할 때

`./start.ps1`로 시작하면 **작업 폴더의 Python 소스**를 직접 읽습니다. `src/`의 AI 모듈과 `tools/bench/`의 Python 연결 코드를 수정하면 서버가 자동 재시작합니다. 화면 상단의 `작업 폴더 연결 · Python 자동 반영 켜짐`을 확인하세요.

1. 원하는 모듈의 Python 파일을 수정하고 저장합니다.
2. 서버가 실행 중인 요청의 완료·저장을 기다린 후 새 코드를 읽습니다.
3. 화면에서 해당 기능을 실행합니다. 다음 실행은 수정된 코드를 사용합니다.
4. 개발자 영역에서 모듈별 서버 코드와 파일 코드가 같은지 볼 수 있습니다.

재시작 중에는 잠깐 연결이 끊길 수 있습니다. 코드 반영 전에 새 유료 호출이 들어오면 `SOURCE_RELOAD_REQUIRED`를 반환하며 호출하지 않습니다. 문법 오류가 있으면 자동 재시작이 완료되지 않으므로 실행 터미널의 오류를 수정해야 합니다. 자동 반영을 끄려면 `./start.ps1 -NoReload`로 실행합니다.

HTML·JS·CSS 변경은 서버 재시작 없이 제공됩니다. 이미 열린 화면에는 `화면 코드 변경됨 · 입력 보관 후 새로고침` 버튼이 나타납니다. 저장된 대화와 계획을 보존하며, C에서 작성 중인 수정 내용도 같은 초안에 한해 복원합니다. API 키 등 환경변수 변경은 시작 스크립트를 종료하고 다시 실행해야 합니다.

## 기존 결과는 어떻게 되나요?

코드 변경은 **이미 만든 계획을 자동으로 고치거나 AI를 자동 호출하지 않습니다.** 기존 결과에는 다음과 같이 표시합니다.

| 표시 | 의미 |
|---|---|
| 현재 코드로 생성됨 | 결과의 `meta.source_revision`이 현재 모듈 코드와 같음 |
| 이전 코드로 생성됨 | 생성 이후 해당 모듈 또는 공통 의존 코드가 변경됨 |
| 이전 기록 · 코드 정보 없음 | 이 기능 도입 전에 저장된 기록. 생성 코드 버전을 확인할 수 없음 |
| 모듈 변경 반영 대기 | 파일은 변경됐지만 서버가 아직 새 코드를 읽지 못함 |

이 표시는 **코드 출처**이며, 입력 내용의 최신 여부나 AI 품질 통과 판정과는 다릅니다. 입력 변경은 별도로 `이전 입력 기준`으로 표시합니다. 사용자가 확인·수정한 조건은 코드가 바뀌었다는 이유만으로 삭제하지 않습니다.

변경된 코드의 결과가 필요하면 해당 모듈을 다시 실행하세요. 새 실행에서는 이전 코드 결과를 성공 캐시로 재사용하지 않습니다. 명시적으로 새 안을 요청하면 같은 입력이어도 다시 호출합니다. 같은 사용자 동작 ID의 재전송은 중복 실행 방지를 위해 원래 결과를 반환합니다.

상태 조회·화면 복원·코드 변경 감지는 유료 API를 호출하지 않습니다. 실행 메타의 코드 식별값은 소스 파일 해시이며 API 키의 일부나 지문이 아닙니다.

## SW팀 서버에 연결할 때

- **AI팀이 운영하는 화면/API를 iframe으로 연결:** AI팀 서버를 새 코드로 배포하면 그 서버의 다음 실행부터 적용됩니다. SW 화면 코드에 AI 로직을 복사하지 마세요.
- **Python 패키지를 SW 서버에 설치:** 이 폴더를 수정해도 SW 서버의 설치본은 바뀌지 않습니다. 새 wheel을 전달하고 SW 서버에서 패키지를 업데이트한 뒤 해당 프로세스를 재시작해야 합니다.
- **로컬 공동 개발:** 이 저장소의 `start.ps1`은 `--app-dir src`로 실행하므로 이전에 설치한 wheel 대신 작업 중인 소스를 사용합니다.

M1-A~F의 공개 입력·출력 계약은 유지합니다. `Result.meta.source_revision`은 추가된 선택 필드이므로 예전 기록도 계속 읽을 수 있습니다. SW가 결과를 저장할 때 전체 `meta`도 같이 저장하면 생성 당시 코드를 추적할 수 있습니다.
