# 킥오프 삽입 데모 · 3단계

이번 단계는 **확인한 공동 조건 → 공동 실행 계획 / 개인 기여 초안 검토 → 개인 실행 계획 → 코드 검증**입니다. 로그인·실제 SW 권한·그룹 승인·서비스 활성화는 아직 포함하지 않습니다.

## 화면에서 사용하는 순서

1. **실행 계획 → 공동 계획 만들기**를 누릅니다. 구성원별 개인 프로필이 없어도 확인한 공동 조건으로 D를 실행합니다.
2. **개인 코칭 → 실행안 정리** 또는 **실행 계획 → 기여 목표 검토·개인 계획**을 누릅니다. 본인 대화와 역할로 E.draft가 기여 초안을 작성합니다.
3. 검토 창에서 기여 목표·결과물·완료 기준·수준·주간 가능 시간을 수정·확인합니다. 모르는 개인 시간·수준은 임의로 채우지 않습니다. 같은 창에서 입력할 수 있으며 A로 돌아갈 필요가 없습니다.
4. **이 내용으로 개인 계획 만들기**를 누릅니다. 확인과 개인 조건 동기화는 코드 처리이고, E.plan만 실제 GPT 호출입니다.
5. 계획 화면에서 과제·마감·예상 시간·완료 기준·주차별 성과·코드 검사 결과를 확인합니다. JSON으로 저장할 수 있습니다.

공동 계획이 먼저 생성돼야 개인 계획을 만들 수 있는 것은 아닙니다. E는 확인한 공동 조건과 본인 조건만 있으면 독립 실행됩니다. 다른 구성원의 개인 정보가 없거나 생성에 실패해도 현재 사람의 계획을 만들 수 있습니다.

## API와 재사용

| API | 기능 |
|---|---|
| POST `/api/kickoff/groups/{id}/plan` | 공동 계획 생성, action_id와 선택적 fresh |
| POST `.../{id}/members/{member_id}/contribution/draft` | 개인 기여 초안 작성 |
| POST `.../{id}/members/{member_id}/contribution/confirm` | 기여 목표·조건 확인, 코드 처리 |
| POST `.../{id}/members/{member_id}/plan` | 확인한 개인 조건으로 실행 계획 생성 |

변경 없는 성공 결과는 DB에서 재사용합니다. **새 공동 계획 / 새 개인 계획**은 fresh=true로 실제 재생성을 요청하고 이전 plan_version_id를 연결합니다. 기존 버전은 삭제하지 않습니다. 생성 실패 시 이전 성공 결과를 보존합니다.

공동·개인 계획의 기간·담당자·시간 예산은 기존 F 코드로 검사합니다. 전달되지 않은 전체 구성원 완성 여부·서비스 권한·최종 승인·의미적 품질은 미검사로 표시합니다. 초안은 자동 활성화되지 않으며 integration_ready는 false입니다.

## 저장·개인정보

공동 계획은 PUBLIC, 개인 조건·기여 검토·개인 계획은 해당 구성원의 PRIVATE에 저장합니다. 공개 그룹 응답에 개인 계획을 자동 게시하지 않습니다. 개인 프로필 수정·확인값은 코칭 상태에도 반영합니다. 새 대화·조건으로 결과가 오래됐으면 이전 조건 기준으로 표시하고 재검토를 요구합니다.

## 아래는 이전 단계 기록

# 킥오프 삽입 데모 · 2단계

이번 단계는 **공동 코칭 → 목표 검토 → 공동 조건 확인 → 개인 코칭**입니다. 공동·개인 실행 계획 생성과 SW 로그인·권한 연결은 다음 단계입니다.

## 새 사용 순서

1. 대화 입력창 옆 **대화 참여자 → ＋ 사람 추가**에서 사람을 직접 추가합니다. 추가한 사람은 즉시 선택됩니다. 인원수는 고정하지 않습니다.
2. 오른쪽 **목표 검토 → 대화로 목표 정리**를 누릅니다. B 분석과 C 초안 작성만 실제 GPT로 실행합니다.
3. 카드에서 날짜·목표·완료 기준·인증·공개 범위·역할을 수정하고 수락합니다. 직접 수정·수락·공동 조건 확인에는 GPT를 호출하지 않습니다.
4. **공동 조건 확인 · 개인 코칭으로**를 누릅니다. 조건 검토이며 실제 그룹 투표·서비스 활성화를 대신하지 않습니다.
5. 개인 코칭 대상을 고르고 시작합니다. 질문 바로 아래 답변 버튼 또는 자유 입력으로 이어갑니다. 이미 답한 버튼의 중복 제출은 반영하지 않습니다.
6. 새로고침하면 검토표와 본인별 대화·상태를 DB에서 복원합니다. 공개 채팅에는 개인 원문을 넣지 않습니다.

## 이번 단계의 경계

- 개인 코칭은 확인한 공개 목표·본인 역할과 해당 구성원의 개인 대화·상태만 모델에 전달합니다.
- 개인 대상 선택은 **로컬 테스트 기능**입니다. 운영 인증이 아니며, 다른 주소의 SW 서비스에 바로 공개할 수 없습니다.
- 새 공개 대화나 구성원 변경 후에는 이전 확인을 조용히 유지하지 않고 재검토가 필요하다고 표시합니다. 개인 대화는 삭제하지 않습니다.
- 검토표가 최신이면 같은 정리 요청은 기존 결과를 사용합니다. B 성공 후 C 실패 시 저장된 유효 B 결과를 재사용합니다.
- 개인 코칭 입력은 API 호출 전에 저장하며 실패해도 보존합니다.

## 추가 API

| API | 역할 |
|---|---|
| POST `/api/kickoff/groups/{id}/review` | B→C 연결, 기존 성공 단계 재사용 |
| POST `.../{id}/review-fields` | 카드 수정·수락, 코드 처리 |
| POST `.../{id}/confirm` | 공동 조건 검사·확인, 코드 처리 |
| GET `.../{id}/members/{member_id}/personal` | 해당 사람의 대화·상태 복원 |
| POST `.../{id}/members/{member_id}/personal/coach` | 자연어 또는 질문 ID·선택지 ID로 개인 코칭 |

`action_id`는 같은 동작의 네트워크 재시도에 재사용합니다. 바뀐 입력은 새 동작 ID를 사용합니다. 질문 ID가 현재 질문과 다르면 409이며 모델을 호출하지 않습니다. 코어 A~F의 독립 호출 계약은 유지합니다.

## 아래는 1단계 구현 기록

### 1단계 기록

**완료 범위:** AI팀이 제공하는 그룹 채팅＋접이식 공동 코칭 패널. 구성원은 목록으로 처리하고 2명으로 고정하지 않습니다. 개인 코칭·계획 검토·SW 계정 인증은 다음 단계입니다.

## 실행과 확인

1. 기존처럼 `./start.ps1`로 서버를 시작합니다.
2. `http://127.0.0.1:8010/kickoff-demo`를 엽니다. 바깥 헤더·사이드바는 SW 화면을 가정한 틀입니다.
3. 안쪽 AI 화면에서 그룹 이름과 구성원 닉네임들을 입력합니다. 구성원 입력 행을 원하는 만큼 추가할 수 있습니다.
4. 생성 후에도 **구성원 보기·추가**에서 사람을 추가할 수 있습니다. 테스트 발언자를 바꿔 대화합니다.
5. **AI 도우미**를 열고 **AI에게 코칭 요청**을 누릅니다. 실제 Timely GPT가 응답합니다. 키가 없으면 명확히 실패하며 가짜 응답으로 바꾸지 않습니다.
6. 새로고침하면 마지막 대화를 복원합니다. 같은 대화 링크를 두 탭에서 열면 2.5초 간격의 조회로 새 메시지가 반영됩니다. 조회에는 모델 호출이 없습니다.

## 이번에 SW가 확인할 것

<!-- 이번 단계는 같은 주소의 로컬 삽입만 검증합니다. -->

채팅·코칭 UI 전체가 AI팀 영역입니다. SW팀이 A의 응답 화면을 다시 작성할 필요는 없습니다. `SW 개발자 연결`을 펼치면 현재 실제 요청·응답과 코어 Python 호출 예제가 표시됩니다.

## 작은 HTTP 계약

| API | 역할 | GPT 호출 |
|---|---|---|
| POST `/api/kickoff/groups` | title과 가변 길이 members 목록으로 생성 | 없음 |
| GET `/api/kickoff/groups/{id}` | 공개 대화·구성원·코칭 복원 | 없음 |
| POST `.../{id}/members` | member_id·nickname 추가 | 없음 |
| POST `.../{id}/messages` | message_id·member_id·text 저장 | 없음 |
| POST `.../{id}/coach` | action_id·선택적 fresh로 A 코칭 | 새 입력/명시적 새 제안만 |

메시지 ID는 중복 전송 방지에 사용합니다. 같은 ID를 다른 내용으로 바꾸면 409입니다. 코칭 action_id를 재전송하면 저장된 같은 결과를 확인합니다. 발언·구성원이 바뀌지 않았다면 새 코칭 버튼 재클릭도 이전 성공 결과를 반환합니다. `fresh=true`는 새로운 유료 제안을 요청합니다.

개인 정보는 이 공개 채팅에 넣지 않습니다. PostgreSQL의 PRIVATE 자료는 공개 응답에서 제외합니다. AI 코칭은 공개 메시지와 구성원만 사용합니다. 200개를 넘는 대화는 최근 200개를 참고한다고 경고하고, 전체 기록은 보존합니다.

## 저장과 범위

대화·실행·목표를 동일 PostgreSQL에 저장합니다. `WEMEET_RECORD_DB`와 SQLite fallback은 정상 경로에서 제거했습니다. [저장·복구 계약](POSTGRES_INTEGRATION.md)을 참고하세요. AI 코어는 DB를 import하지 않고 어댑터가 입력·결과를 저장합니다. 입력 중인 미전송 문장은 현재 브라우저에만 임시 보관하고, 전송된 메시지는 AI 서버 DB에 저장합니다. 일반 채팅과 AI 응답은 화면에서 분리하지만 같은 그룹 문맥으로 다음 코칭에 사용합니다.

**운영 연동으로 오해하지 마세요.** 현재 발언자 선택·그룹 링크는 로컬 테스트용이며 서비스 로그인·권한이 아닙니다. 서버는 127.0.0.1에서 사용하세요. iframe은 `frame-ancestors 'self'`로 제한합니다. 실제 SW의 다른 주소 연결, 인증된 본인·그룹 전달, 실시간 운영 채팅, 비공개 E 코칭과 계획 전달은 다음 단계에서 구현합니다. 아직 공개 서버에 배포하지 않습니다.

## 1차 검증 결과

- 회귀 검사 137개 통과. 구성원 1·3·7·25명과 생성 후 추가를 검사했습니다.
- 브라우저에서 3명 생성 → 4명째 추가 → 다른 발언자의 메시지 → 실제 GPT 코칭 → 새로고침 복원을 확인했습니다.
- 실제 GPT HTTP 2회, 첫 발언자 경험 오인 사례를 보존하고 보완 후 정확한 연결을 확인했습니다. 지연시간은 9,907ms / 8,417ms입니다. 한 익명 사례의 에이전트 검토이며 전반적 품질 보증은 아닙니다.
- 기본 데스크톱과 390×844에서 채팅 입력과 AI 패널 열기·닫기를 확인했습니다.
- 키 검사와 소스/wheel 일치 검사 통과. 기존 사용자 DB는 유지했습니다. 자세한 결과는 `kickoff-phase1-verification.json`을 확인하세요.

## 2단계 검증 결과

- 전체 회귀 검사 142개 통과, 공동 조건 변경 방어 보완 후 관련 5개 재검사 통과.
- 실제 GPT로 B→C 검토표 작성, 브라우저에서 목표·인증·역할 수정·수락→공동 조건 확인→개인 코칭→주 1시간 답변 버튼을 확인했습니다.
- 확인·수정·저장 복원은 코드 처리입니다. 성공한 입력의 재정리는 추가 호출 없이 기존 결과를 반환합니다.
- 서버 재시작 후 확인한 목표와 개인 60분 조건을 복원했습니다. 공개 응답에서 개인 메시지 ID가 제외되고 다른 구성원에게 해당 대화가 나타나지 않는지 검사했습니다.
- 이번 단계 신규 실제 HTTP는 4회, 17140 tokens입니다. 재시도·보정도 포함한 실행 메타 기준입니다. 익명 사례의 에이전트 검사이며 사람의 인수 완료나 실제 운영 인증 완료가 아닙니다.

## 모듈 수정과 화면 반영

`start.ps1` 기본 실행은 작업 폴더의 Python 모듈을 자동으로 다시 읽습니다. 다음 사용자 실행부터 새 코드가 적용되며 기존 확인값·계획은 보존됩니다. 화면 수정·캐시·SW 설치본 업데이트의 차이는 [코드 변경 반영](CODE_UPDATES.md)에 정리했습니다. 최신 검사 결과는 [0.13.1 검증 기록](code-updates-verification.json)을 확인하세요.

## 3단계 검증 결과

- 최종 전체 회귀 검사 148개 통과. 개인 프로필이 0명이어도 D 생성, D 없이 E 생성, 미확인 조건 차단, 버전 연결, 한 사람 실패 후 다른 사람 진행을 검사했습니다.
- 실제 GPT로 D 공동 계획 → E.draft 기여 초안 → 브라우저 검토 → E.plan 개인 계획을 확인했습니다. 이번 단계 실제 HTTP 3회, 9961 tokens입니다. 성공한 동일 계획의 재실행은 DB 결과를 재사용합니다.
- 주 60분 조건에서 주차별 예상 시간은 {1: 60, 2: 60}분이며 F 코드 검증을 통과했습니다. 코드 검사 통과는 의미적 품질·운영 승인 완료를 뜻하지 않습니다.
- 서버 재시작 후 공동·개인 계획, 확인 프로필, 코칭 상태를 복원했습니다. 공개 응답에 개인 계획이 들어가지 않고 다른 구성원의 계획과 섞이지 않는지 확인했습니다.
- 실제 사람의 승인 대신 익명 기준 입력을 검토한 개발 테스트입니다. 개인정보의 우회 표현까지 코드로 완벽히 판별했다고 주장하지 않습니다.
